# AI 套图工作台 使用说明

采集 1688 服装商品 → 选 SKU（颜色）和你的商标 → AI 生成一整套 Wildberries 上架图（首图带卖点、模特图、细节图等），
商标直接印在左胸。同一个 SKU 换商标时只重做印标的那几张。生成好的套图移入「待上架」，填好资料后直接上架到 Wildberries（也可以导出图片）。

## 启动

1. 双击仓库根目录的 **`启动印标工具.bat`**。
2. 第一次运行会自动检查 Python、安装依赖（国外源慢会自动切换国内镜像）。
3. 浏览器自动打开 `http://127.0.0.1:8765`。**使用期间不要关闭黑色命令行窗口。**

## 第一次使用要做的设置

### 1. 中转站（设置 → AI 中转站）

- **接口地址**：如 `https://www.xpivot.top/v1`
- **令牌**：中转站「令牌」页面生成的 API Key
- **生图模型**：`gpt-image-2`
- **商品理解模型（可选）**：填一个能看图的对话模型（如 `gpt-4o-mini`），AI 会先看一遍商品，写出商品描述、俄语卖点、俄语标题和首图大字。不填也能用（卖点可以手动写）。尺码表不需要它。
- **调用方式**：保持「自动适配」。程序会先试图片编辑接口，不支持再改用对话接口，并记住能用的那种。
- 点「测试连接」确认能连上。

### 2. 套图模板（设置 → 套图模板）

- 每套 5～8 张（AI 生成），默认 6 张，参照 WB 头部商品的风格，**不用模特**，前两张讲卖点，后面讲细节和功能：
  1. 首图：衣服正面（隐形人台）+ 胸口 logo；左上角品牌 logo、左侧一列卖点（图标 + 俄文）、右侧颜色圆点、底部半透明大字
  2. 背面图：左上 logo + 另外几条卖点 + 颜色圆点 + 大字
  3. 保暖结构剖面图：面料 / 填充 / 内里分层 + 俄语标注
  4. 内里 / 保暖层特写 + 俄语标题说明 + 图标（只拍局部）
  5. 面料特写（防水、质感）+ 俄语说明（只拍局部）
  6. 细节拼图：拉链、口袋、袖口、领口等 3~4 个特写（只拍局部）
- **尺码表固定放在每套最后一张**（6 张时就是第 7 张），全部在本地完成，不调用任何接口：
  - 用本地 OCR（文字识别，离线）从详情图里找到尺码表并读出数字；
  - 表头按内置对照表翻译成俄文（衣长 → Длина изделия、胸围 → Обхват груди、肩宽 → Ширина плеч、袖长 → Длина рукава、身高 → Рост, см、体重 → Вес, кг 等），体重的"斤"自动换算成公斤；
  - 识别结果显示在右侧「尺码表」里，可以核对和修改；对照表里没有的表头会保留中文，手动改一下即可。
- 以上就是「推荐模板 1」。张数选 7、8 时，依次加上「功能演示（风雪中的面料防护）」「面料微距」。设置里可以随时「恢复推荐模板 1」。
- **风格**：模板决定每张拍什么，风格决定背景场景、色调和叠加层配色。生成时在右侧选：经典棚拍、冬日雪景、暖调奶咖、高级深色、城市街景、活力撞色，或「随机风格」（每套随机一种）。同一个颜色可以用不同风格各生成一套。也可以改回带模特的类型。
- 首图、背面图上的左上 logo、卖点栏、颜色圆点、底部大字都由程序本地叠加：logo 用你上传的原图（黑色），颜色圆点取自各 SKU 图，俄文不会出错。
- **卖点**：配置了「商品理解模型」时由 AI 写（推荐，每个商品 1 次）；没配时自动从标题和详情图文字里提取（本地、免费）。右侧可以随时修改，改完自动更新已生成的图（不花钱）。首图显示前 3 条，背面图显示第 4~6 条；没有卖点时显示尺码区间。
- **胸口 logo 颜色**：默认黑白自动——浅色衣服印黑色，深色衣服印白色（Logo 库里可改为保持原色）。
- **logo 印法**（设置里选）：
  - AI 局部放大印标（推荐）：AI 先在胸口放一个占位块确定位置，再把胸口放大交给 AI 印上你的 logo，最后只把这一小块贴回去。logo 还原度高、质感自然；每张胸口印标的图多 1 次调用。
  - 本地贴 logo 原图：不额外调用，和原图 100% 一致，但质感偏平。
  - AI 整张直接画：最省，但 logo 容易走样。
- 每个位置可以写额外要求，比如"背景用浅米色"。
- 卖点文字语言默认俄语。

### 3. 风格参考图（可选）

上传 1～2 张你喜欢的 WB 商品图截图。生成首图时 AI 会参考它的拍摄风格和排版，不会照抄商品。

### 4. Logo 库

上传你自己的商标（透明底 PNG 最好），可以选工艺（印花 / 刺绣 / 胶印 / 织标）和颜色（自动与衣服撞色 / 保持原色）。

### 5. 安装「采集助手」Chrome 扩展

1. Chrome 地址栏输入 `chrome://extensions`，打开右上角的「开发者模式」。
2. 点「加载已解压的扩展程序」，选择 `logo-studio\chrome-extension` 文件夹。
3. 刷新工作台页面，右上角显示「采集助手已连接」即可。
4. 以后更新程序后，在扩展页点一下「采集助手」上的刷新按钮。

## 日常流程

1. **采集**（都在你自己的 Chrome 里进行，只保存图片链接，不下载图片）
   - 商品页右下角的「采集到印标工作台」按钮，点一下即采集；
   - 或在「采集 1688」里粘贴商品链接 / 店铺链接批量采集；
   - 或开好一批商品标签页，点「采集已打开的标签页」。
2. **生成套图**：左侧选商品 → 勾选 SKU 卡片左上角的方框（要做的颜色）→ 右侧选 logo 和风格 → 点「生成套图」。点击 SKU 卡片本身，下方只显示这个颜色的套图，再点一次显示全部。
   - 每个 SKU 生成一套。SKU 图决定"商品长什么样"，主图和详情图只帮 AI 理解细节。
   - 按钮下方会显示这次要调用生图多少次。
   - 右侧「AI 商品理解」里可以改模特性别、首图卖点、尺码表、俄语标题，改过的内容不会再被 AI 覆盖。
   - 尺码表：生成时自动从详情图识别（也可以点「从详情图识别」）；也可以手动填写，每行一个尺码，用 `|` 分隔，第一行是表头。
3. **检查和修改**
   - 点任意一张图看大图；不满意就写下修改要求（如"logo 再小一点"），重新生成这一张。
   - 失败的图点「重试」即可。
4. **换商标**：在已生成的套图上选「换成其他 logo…」，会得到一套新的图：衣服底图全部沿用，只重新印胸口 logo（默认模板只有首图，1 次调用），左上角 logo 等在本地重新叠加。
5. **移入待上架**：满意的套图点「移入待上架」。也可以在「待上架」页勾选后导出图片（每套一个文件夹，01 是首图），导出目录在 `logo-studio/data/exports`。
6. **上架到 WB**：见下面「上架到 Wildberries」。

## 上架到 Wildberries

### 绑定店铺（一次）
「待上架」→ 右上角「店铺管理」→ 填店铺名和 WB API 令牌 →「验证并绑定」。
- 令牌在 WB 卖家后台 → 设置 → API 访问 生成，类型选「标准」，勾选 **内容（Content）**、**价格和折扣（Prices）**、**市场（Marketplace）**。
- 令牌只保存在本机 `data/shops.json`，页面上只显示末 4 位。可以绑多个店铺，右上角切换当前店铺。
- 「测试权限」会分别检查三个权限；「写库存的仓库」不选时自动用第一个仓库。
- 「供应商编码前缀」是防重复建卡的依据，设好以后不要再改。

### 一张商品卡怎么来的
同一个 1688 商品 + 同一个 logo 的所有待上架套图，合成 **一张 WB 商品卡**，每个颜色是卡里的一个款式（共用尺码）。同一个颜色有好几套图时，默认用最新的一套，可以在编辑里切换。

### 1688 商品怎么对应 WB 类目
- 编辑框里点「**自动匹配**」：按 1688 标题里的品类词（冲锋衣、卫衣、T恤、牛仔裤…）在 WB 的真实类目里找候选；设置了「商品理解模型」时由 AI 从候选里选一个，否则取关键词的第一个候选。下面会列出其他候选，点一下就能换。
- 你给某类商品选过一次类目（保存后），以后同类商品（同一个品类词）直接用你选的，不再问 AI。
- 「批量 AI 填写」会对没选类目的卡自动匹配类目。

### 按商标分开看
待上架页顶部的商标选项卡：「全部商标 / 一号商标 / 二号商标…」，只看用某个商标印的商品卡。

### 批量操作（先勾选商品卡）
- **批量 AI 填写**：自动匹配类目，并填写俄文标题（每个颜色单独一个标题）、说明、属性、包装尺寸重量、海关编码。每张卡约 2–3 次 AI 调用，填完请抽查。
- **批量修改价格/折扣/重量/库存/尺寸**：价格公式或固定价、折扣率、包装长宽高和重量、库存，只改填了的项。勾选「同步到 WB」时，已上架的卡会把新的价格和折扣直接更新到 WB。
- **批量上架选中**：先逐张预检，全部通过才开始。

### 一个商品后来又加了颜色
同一商品 + 同一商标的卡上过 WB 以后，再生成新颜色移入待上架、点上架：已在 WB 的颜色直接续传，新颜色**追加进原来那张商品卡**（WB 上显示为同一商品的不同颜色），不会另建一张卡，也不会因为「编码已存在」失败。如果 WB 上同一商品的颜色被拆成了几张卡，上架时会自动合并。

### 上架诊断（推荐第一次上架前做一次）
- 到 WB 的线路慢时，程序会复用连接，减少每次请求的等待。
- 某个接口被 WB 长时间限流时，程序在冷却时间内不再请求它（反复请求会让限流越来越长），颜色等目录先用缓存或内置的常用列表。

「店铺管理」→「上架诊断」：只读检查上架要用到的所有 WB 接口（不创建、不修改任何商品），选一张上架单还会做预检并生成「将要提交给 WB 的商品卡」预览。报告保存在 `data/wb_diag`，不含令牌，有问题可以直接把这个文件发给开发者。

### 填写资料
点卡片上的「填写上架资料」：
1. **类目**：搜索中文或俄文（例如「夹克」或「Куртки」），点选。
2. **基本信息**：俄文标题（≤60 字符，不能有性别词，上架时会自动清理）、品牌（必须是你在 WB 上已注册/已获授权的品牌）、生产国、ТН ВЭД、库存、俄文说明。
3. **款式**：每个颜色可以选 WB 官方颜色（下拉提示），可以单独写款式标题。颜色只有在类目要求必填时才必须填，否则可以不填。
4. **尺码**：自动从 1688 尺码取卖家尺码和俄码（M→48、L→50…），可以改；采购价可以手动覆盖。
5. **价格**：公式 `(采购价 + A) × B + C`，或固定价；再设折扣率（0–99%），上架时价格和折扣一起提交到 WB。同一款式所有尺码同价（取最高）。已上架的卡改了价格/折扣后点「保存并同步价格和折扣到 WB」。
6. **包装尺寸和重量**。
7. **属性**：类目的必填和常用属性；勾选「显示全部属性」看全部。

「**AI 填写**」会用设置里的「商品理解模型」看图填写标题、说明、属性、颜色、ТН ВЭД 和包装估算。官方目录里没有的值会被丢弃并在下面列出来——**AI 填完一定要逐项核对**。

### 预检和上架
- 「预检」只在本地检查（加上 WB 品牌库查询），不会写入 WB。红色问题必须处理，黄色是提醒。
- 「保存并上架」/卡片上的「上架」会先预检，再弹窗确认，**确认后才会真实写入 WB**。
- 上架步骤：查已有卡 → 生成条码 → 创建商品卡 → 等待生效 → 上传图片 → 价格和折扣 → 库存。进度显示在卡片上，日志在编辑框底部。
- 「批量上架选中」会先逐张预检，全部通过才开始，按顺序逐张上架。

### 安全设计（为什么可以放心点「续传」）
- 供应商编码是固定的（前缀-1688商品ID-logo-颜色序号），第一次上架时就保存在上架单里，以后改前缀也不变。上架前先按编码查 WB：已经存在就直接续传，不会重复建卡；在回收站里就恢复原卡。
- 只有一个「均码」的商品按无尺码商品上架（不会把中文「均码」提交给 WB）。
- 创建商品卡的请求只发 1 次。网络超时或 WB 返回 5xx 时不重发，只按编码回查。
- 图片每传成功一张就记一次断点，失败后再点「续传」只补传剩下的。
- 新卡的尺码还没同步到库存服务时（WB 返回 409），状态显示「库存同步中」，后台按 20/40/80… 秒自动重试，程序关掉重开也会接着重试。
- 程序在上架中途被关掉，重开后这张卡显示「失败」，再点「续传」即可。
- 被 WB 限流时会自动等待；需要等很久时会提示稍后再试。

**建议：第一次先用一个商品、一个颜色试上架，到 WB 后台确认商品卡、图片、价格、库存都正确后，再批量上架。**

## 常见问题

- **页面空白 / 界面没变化**：更新后双击启动时，程序会自动关掉还在运行的旧版本再启动新版；如果仍不对，关掉所有黑色窗口重新双击，并在浏览器按 Ctrl+F5。
- **生成失败**：图片下方会显示中转站返回的原因（余额不足、令牌错误、模型名不对等）。完整信息在 `logo-studio/data/logs/error.log`。
- **生成的衣服和 SKU 不一样**：在大图里写明哪里不对（如"拉链是黑色的，领子是立领"）后重新生成；或者配置「商品理解模型」，让 AI 先看懂商品。
- **生成的图保存在哪**：`logo-studio/data/products/商品ID/sets/` 下，删除套图或商品前一直保留。
- **费用**（默认模板）：生成一套 = 6 张 AI 图 + 首图胸口印标 1 次 = 7 次生图调用，尺码表免费；换一个商标 = 1 次；尺码表本地识别，不花钱；商品理解（可选）每个商品 1 次。
- **详情图是 0**：更新程序后，在 `chrome://extensions` 刷新「采集助手」（版本 1.2.0），回到商品页重新点「采集到印标工作台」即可（已生成的套图会保留）。还是 0 的话，把 `logo-studio/data/debug/` 里的「商品ID-详情图.json」发给开发者。
- **采集失败 / 解析失败**：失败的商品会在 `logo-studio/data/debug/` 留下调试文件，发给开发者即可适配。
- **验证码频繁**：在设置里调大「每个商品间隔」，同一账号一天不要采太多。
- **数据在哪**：全部在 `logo-studio/data/`（商品、生成的套图、logo、导出、设置）。

## 说明

请只使用你拥有或已获授权的商标。AI 生成的商品图应与实际发货的商品一致（颜色、款式、logo），上架前请逐张检查，避免图文不符。
